# 캐릭터 제작·게임 적용 기준

현재 선택창은 원이, 리브, 미나미, 메이 핫걸단, 메이 큣걸단, 제나 여섯 항목입니다. 기본/1/2 같은 별도 번호나 이전 절차형 아바타는 선택창에 표시하지 않습니다. 이전 `minami-pink` 저장값은 `minami`로 이전합니다. 삭제된 `default`와 알 수 없는 선택은 원이로 이전합니다.

- 애니풍의 넓고 불투명한 머리 형태를 사용합니다. 가는 섬유·빗자루형 잔머리를 만들지 않습니다.
- 원이/제나 가발은 정수리부터 옆·뒷머리와 끝단까지 하나의 연결된 닫힌 표면입니다. 따로 만든 두피와 긴 튜브를 단순히 합쳐 일체형이라고 부르지 않습니다. 실제 연결 성분과 열린 경계를 검사합니다.
- 미나미 핑크캡은 귀를 모자 표면에서 조형하고 챙 시작점을 왕관 부분과 공유합니다. 분리된 삼각형 귀를 얹지 않습니다.
- 사진에 없는 머리·장식을 임의로 추가하지 않습니다. 승인된 리브 v5·메이 머리 형태는 유지합니다.
- 공통 `standard-lean-v2` 체형을 사용합니다. 얼굴·몸통·팔·다리의 공통 변형과 골격을 유지하고, 모자를 제외한 몸 기준 높이를 2.95로 맞춥니다. 바운딩박스에 포함된 모자 때문에 몸이 줄어들지 않게 합니다.
- `standardize_sd_body.py`의 매끈하고 가는 다리 프로필을 사용합니다. 옷의 오버핏/와이드 핏은 참고 의상에 맞춥니다.
- 발 원점은 0으로 통일합니다. 모자·장식은 높이에 자연스럽게 더해지며 닉네임은 장식 위에 표시합니다.
- 얼굴 아틀라스는 2048 해상도로 베이크하고 게임용 UV만 남겨 경계선과 잘못된 텍스처 매핑을 방지합니다.
- 게임 카메라는 유령 관전석 쪽의 2.5D 원근 시점이며 바닥 기준 24도로 좌우 회전 없이 무대 가로선을 수평으로 유지합니다. 모든 화면에서 같은 고정 가로형 맵을 유지합니다. PC·가로 화면은 전체 맵을 보고 세로 화면은 캐릭터 주변을 보여주며 카메라 위치만 좌우로 부드럽게 추적합니다. 이동 중 각도·확대율과 맵·캐릭터 비율을 유지하고 캐릭터는 이동 방향으로 회전하며 이름표도 함께 따라갑니다. 관절·재질은 참가자마다 독립적입니다.

GLB는 `../client/assets/models/`에 있습니다. 원본 승인 리브 가발은 `liv-v5/liv-solid-anime-wig-v5.blend`로 보존합니다. 의상 원본과 게임용 편집 원본 `.blend`도 각 캐릭터 폴더에 보관합니다. 얼굴과 손은 사용자가 제공한 애니 모델 베이스를 활용하며 새 의상과 가발을 구성합니다.

탈락 시 GLB 전체를 숨기고 기존 연보라색 유령 스프라이트로 전환합니다. 부활 시 같은 GLB 인스턴스를 다시 표시하며 선택한 아바타와 원래 재질을 유지합니다. 유령 스프라이트는 참가자별 재질을 사용하고 공용 텍스처를 해제하지 않습니다.

PC·모바일 모두 사용자가 `저사양 모드` 버튼으로 표시 방식을 선택합니다.
기본값은 꺼짐이며 브라우저에 선택을 저장합니다. 켜면 본인은 선택한 정밀
아바타를 유지하고 다른 생존자는 둥근 머리와 역원뿔 몸통의 간단한 SD로
표시합니다. 팔·다리·헤어는 만들지 않으며 이동 방향, 색상과 닉네임은
유지합니다. 공유 InstancedMesh 세 개, 사람당 264삼각형을 사용합니다.
탈락자는 기존 연보라 유령으로 전환합니다. 모드를 꺼도 같은 캐릭터·채팅·
이동 상태를 유지하고, 정밀 아바타 복원은 프레임당 최대 두 명·3ms의
시작 예산으로 나누어 처리합니다. 개별 모델 생성 자체를 중간에 끊는 것은
아닙니다. 생성한 정밀/SD 인스턴스는 해당 참가자가 나갈 때까지 재사용하며
퇴장 시 두 캐시를 모두 정리합니다. 메모리 감소보다 렌더링 부담 완화에
초점을 둡니다. 일반 모드 입장 시에는 모델 없는 로딩 상태에서 같은
예산으로 정밀 모델을 준비하여 한 번에 100개 모델을 만들지 않습니다.
멤버 GLB 로딩 중 예전 호빵 모델이나 저사양 SD를 임시 표시하지 않습니다.
저사양 SD는 해당 모드를 켰을 때만 사용하며, 아바타 선택 미리보기에는
모델이 준비되기 전까지 ‘캐릭터 불러오는 중…’을 표시합니다.

검증은 실제 게임 GLB의 정면/옆/뒤 렌더, 모든 멤버의 골반·무릎·어깨 높이 일치, 가발/모자 연결 성분, PC·모바일 이동과 유령 표시를 포함합니다.

## 정밀 원격 아바타 배칭

`client/instancedAvatars.js`는 기존 GLB를 변경하지 않고 원격 참가자를
모델·재질별 InstancedMesh로 그립니다. 여섯 모델 각각 7개 메시이므로
본체는 최대 42개 배치이며 닉네임·상태표시·바닥·본인 등은 별도입니다.
본인은 기존 실시간 스켈레톤을 사용합니다. 정점 텍스처를 지원하지 않는
환경에서는 기존 개별 모델 렌더링으로 돌아갑니다.

기존 `AvatarModels.update`로 대기 자세 1개와 걷기 32프레임의 뼈대
변환을 모델당 한 번 굽습니다. 모자와 헤어는 머리 관절을 따라갑니다.
19관절 리그 기준 약 1.61MiB의 애니메이션 텍스처를 여섯 모델 전체가
사용합니다. 모든 정점을 저장하는 VAT가 아니라 뼈대 행렬 팔레트이며
참가자마다 걸음 위상·걷기/대기 혼합·위치·방향을 따로 지정합니다.
주변 두 프레임을 보간하고 원래 걷기 속도 1.5배 정책을 유지합니다.

화면 밖·유령·저사양 표시 중인 참가자는 배치에서 제외하고, 보이는
생존자만 연속 슬롯에 채워 그립니다. 원격 본체의 실시간 그림자 패스는
끄고 기존 발밑 접지 그림자를 사용합니다. 저사양 전환은 기존 캐시를
유지하며 퇴장 시 슬롯을 반환합니다. 고밀도 원본의 삼각형 수는 그대로여서
배칭만으로 모바일 144FPS나 1,000명 성능을 보장하지 않습니다.

`framePacing.js`가 화면 콜백에 맞춰 최대 144FPS를 허용합니다.
게임 규칙 창에서 현재 FPS를 확인하며 실제 휴대폰 검증은 별도로 합니다.

PC는 원래 해상도와 픽셀 비율을 유지하면서 MSAA 대신 Three.js r128의
공식 FXAA 화면 패스를 사용합니다. sRGB 렌더 타깃으로 기존 배경·재질
색을 유지하며 리사이즈 시 실제 그리기 버퍼 크기에 맞춥니다. 모바일은
기존 직접 렌더 경로를 유지합니다. `sceneAntialias.js`의 추가 화면 패스는
그리기 명령 1회/삼각형 2개이며 성능 통계에는 본 장면과 합산합니다.

`crowdDecorations.js`는 다른 참가자의 발밑 접지 그림자를 1개 배치,
O/X·번호·상태 카드를 텍스처별 배치로 그립니다. 본인의 카드와 금빛 링은
기존 경로를 유지하며 본인 카드를 원격 카드보다 앞에 표시합니다.
빈 방·화면 밖·퇴장 상태에서는 해당 인스턴스를 그리지 않습니다.
PC의 원격 닉네임·채팅 위치 계산은 최대 30Hz이며 몸체 이동·보행과 본인
UI는 화면 속도를 따릅니다. 모바일 원격 UI의 기존 갱신 정책은 유지합니다.
PC용 CPU 뼈대 보간 실험은 FPS 이득이 불확실하여 채택하지 않았습니다.

## 19관절 보행 리그

`client/avatarRig.js`가 GLB를 읽은 직후 기존 표면·인덱스·텍스처를
유지하면서 11개 관절에 척추·가슴·목·머리·양 어깨·양 손목을 추가합니다.
원본 GLB와 Blender 소스를 덮어쓰지 않고 게임용 리그를 한 번 준비한 뒤
공유합니다. 기존 기본 자세의 정점 위치를 유지하도록 역 바인드 행렬을
다시 계산합니다. 몸통은 높이에 따라 골반·척추·가슴에, 머리/헤어/모자는
머리에, 팔의 끝부분은 팔꿈치와 손목에 가중치를 배분합니다.
모든 정점은 정규화된 가중치 최대 4개만 사용합니다. 스킨 대상 메시가
4개에서 7개로 늘었으며 몸통의 혼합 변형도 추가되므로 GPU 비용이
동일하다고 보장하지 않습니다. 삼각형 수와 42개 본체 배치는 유지합니다.

걷기는 골반과 가슴의 반대 회전, 머리의 작은 보정, 어깨·손목의 흔들림을
사용합니다. 무릎 들림 곡선의 시작과 끝 기울기를 완만하게 하고 팔꿈치
위상을 엇갈리게 합니다. 이동 속도는 그대로이며 기존 1.5배 보행 템포를
유지합니다. `artifacts/rig19-check.cjs`는 19관절·4영향 제한·정규화·기본
자세 보존·유령/부활 및 합성 100명 배칭을 검증하고 보행 렌더 시트를 만듭니다.

호빵 메시 생성 코드는 `client/avatars.js`에서 삭제했습니다. 이 파일은
승인된 멤버 GLB와 유령을 다루는 `AvatarActors`만 제공합니다.

## 전용 경량 사회자

`client/showHost.js`는 크림색·민트색 안내 로봇을 직접 생성합니다.
몸체·팔다리·마이크는 정점 색상을 가진 단일 메시로 합치고 얼굴은 별도
평면 하나와 작은 표정 아틀라스를 사용합니다. 총 530삼각형, 본체/얼굴
그리기 2회, 뼈대 0개입니다. 실시간 그림자 생성·수신을 하지 않습니다.
기존 리브 사회자의 87,950삼각형·본체 7회보다 렌더링 부담이 작습니다.
멤버 GLB는 플레이어용으로 계속 보존합니다.

표정은 고정 아틀라스의 UV만 바꿔 눈 깜빡임과 말하는 입을 표시하고,
전체 몸체 그룹의 작은 움직임만 계산합니다. 별도의 모델 파일을 내려받지
않으므로 사회자 로딩 교체가 없습니다. 기존 무대/말풍선 앵커를 사용하며
`artifacts/show-host-check.cjs`로 PC·모바일 배치, 표정, 2회 그리기와
그림자/관절 부재를 확인합니다. `QuizPerformance.snapshot().host`에
사회자 자체의 삼각형 수와 본체 그리기 횟수가 나옵니다.

## 폐기된 실험

Plana와 Chibi 버전은 모두 사용자 요청으로 제작을 중단하고 게임에서
제외했습니다. 내보냈던 파일은 각 제작 폴더의 `retired-assets/`에 보관합니다.
게임 선택창과 로더에는 기존 여섯 아바타만 남깁니다. 과거 실험을 선택했던
브라우저는 동일한 멤버의 기존 아바타로 돌아갑니다.
