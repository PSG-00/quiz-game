# 연결 복구와 예약 자리 정리

게임 화면과 로비에 `연결 복구` 버튼을 제공한다. 정상 연결에서는 먼저 해당 소켓으로 최신 ROOM_STATE와 전체 WORLD_TICK을 요청한다. 2.5초 안에 복구 응답이 없을 때만 연결을 교체하며, 새 연결의 재입장이 확정될 때까지 기존 연결을 먼저 닫지 않는다. 이 순서로 대기실 단독 사용자의 방이 복구 중 삭제되는 문제를 막는다. 복귀 토큰이 거절돼도 바로 로비로 보내지 않고 같은 브라우저 식별자로 기존 자리를 찾는 JOIN_ROOM을 한 번 시도한다. 실제 예약이 만료된 경우에는 관전 자격만 부여한다. 최신 상태에는 요청자 자신의 제출 답안만 포함한다. 이미 내려진 탈락 판정을 되돌리거나 유예 만료 이후 참가 자격을 새로 부여하지 않는다.

## 클라이언트: 끊김을 빨리 알아채고 그 자리에서 복귀

자동 동기화는 렌더링 루프에서 분리한 0.5초 간격 점검으로 실행한다. 1초 간격 애플리케이션 ping으로 단계 버전과 서버 시각을 확인한다. 어떤 패킷도 3초 넘게 오지 않는 OPEN 연결(방 안에서는 초당 10번 갱신과 1초마다 ping 응답이 온다), 5초(직접 주소는 3초) 안에 열리지 않는 연결, 2.5초 안에 답이 없는 상태 요청은 기존 연결을 남겨 둔 채 새 연결로 교체한다. 문제가 12~15초뿐이라 조용히 죽은 연결을 오래 기다리지 않는다. 메인 스레드가 1.5초 넘게 멈췄던 직후(무거운 프레임, 백그라운드 복귀)에는 1.5초를 더 기다린 뒤 판단한다. 화면 복귀·`online` 이벤트에서는 즉시 ping을 보내고 2.5초 안에 아무 패킷도 없으면 교체한다.

게임 중 연결이 끊겨도 로비로 보내지 않는다. 무대·캐릭터·타이머를 그대로 둔 채 이동만 멈추고, 재접속(0.25초부터 최대 2초까지 지수 증가 + 임의 분산) 뒤 RESUME_ROOM으로 같은 자리에 복귀한다. 서버 재시작 종료 코드 1012를 받으면 서버가 다시 뜰 시간을 두고 1.2초 뒤부터 재접속한다. 방 자체가 사라졌을 때만 로비로 돌아간다. 다른 창으로 연결이 넘어간 창(4001)은 자동 접속 경쟁을 반복하지 않는다.

타이머 표시는 ROOM_STATE 도착 시각이 아니라 왕복 지연이 가장 작은 ping 표본으로 서버 시각을 추정한다. 혼잡으로 늦게 도착한 상태 메시지가 남은 시간을 앞당겨 0초에서 멈춘 것처럼 보이지 않게 한다. 서버가 반영하지 못한 정지 위치(유실·속도 제한된 MOVE)는 서버가 알려 준 내 좌표와 비교해 다시 보낸다. 자기 좌표를 받기 전에는 MOVE를 보내지 않는다.

## 불안정 회선에서 답안·입장·이동을 잃지 않기

- 답안(주관식·버튼형 객관식)은 서버 확인(ANSWER_ACK, 또는 복귀 때 받는 자기 제출 상태)이 올 때까지 보관한다. 재연결 중이거나 조용히 끊긴 연결에서 누른 답도 자리 복귀 직후 다시 보내고, 확인이 없으면 1.5초마다 다시 보낸다. 0.8초 넘게 확인이 없으면 "전송 확인 중…"을 보여 준다. 끝내 확인되지 않은 채 문제가 끝나면 `answer-unconfirmed` 진단을 남긴다.
- 답안·이동은 마감 직전 (최소 왕복 지연의 절반 + 0.1초, 최대 0.8초) 전에 받기를 멈춘다. 서버가 늦었다고 버릴 답을 화면이 "제출됨"으로 보여 주지 않기 위해서다.
- 입장하려는 방은 JOINED_ROOM을 받을 때까지 기억한다. 입장 요청이 끊긴 연결과 함께 사라져도 다음 연결에서 다시 보낸다. 방 화면이 떠 있는데 복귀 토큰이 없으면(복귀 거절 뒤 재입장 요청이 사라진 경우) 같은 브라우저로 다시 입장해 자기 자리를 돌려받는다. 열린 연결에서 4초 동안 입장 확인이 없으면 새 연결로 다시 시도한다(`join-timeout`).
- 서버가 이동 예산(최대 3m)만큼만 반영한 이동은 되돌리지 않는다. 클라이언트가 멈춘 자리를 계속 다시 보내므로 1초 안에 따라잡는다. 6m가 넘는 순간이동만 거절하고 위치를 바로잡으며, 이때도 눌러 둔 목적지(OX·구역)는 유지해 그쪽으로 계속 걸어간다.
- MOVE는 위치 자체이므로 초당 허용량을 넘은 묶음에서 버리지 않고 가장 마지막 위치만 0.12초 뒤 반영한다. WORLD_ACK는 버리지 않는다(버려지면 월드 전송이 멈춘 채 풀리지 않았다). 연결당 전체 메시지 허용량은 6초 정체 뒤 몰려오는 묶음을 받도록 순간 240개다.
- 재연결 중 누른 채팅·시작·초기화는 오류로 멈추지 않고 "연결을 다시 잡는 중" 안내를 보여 준다.

## 월드 전송: 압축 델타와 응답 기반 흐름 제어

월드 방송은 초당 10회다. 새 클라이언트는 위치만 바뀐 참가자를 `[번호, x*100, z*100]` 정수 묶음(`m`)으로 받고, 다른 변화와 새 참가자는 기존 패치로 받는다. 받은 순번은 0.2초마다 WORLD_ACK로 알린다. Cloudflare 터널 뒤에서는 서버의 `bufferedAmount`가 항상 0에 가까워 느린 폰을 알아챌 수 없으므로, 확인되지 않은 순번이 20틱(2초)을 넘으면 그 연결에만 월드 전송을 멈춘다. 확인이 따라잡으면 전체 상태 한 번으로 재개한다. 게임 상태·채팅·답안 확인은 멈추지 않는다. 숨겨진 탭은 확인을 보내지 않으므로 자동으로 월드 전송이 멈춘다. 플래그를 보내지 않는 이전 클라이언트는 기존 형식과 전송을 그대로 받는다.

## 서버: 예약 자리와 재시작 복원

서버는 대기실을 포함한 모든 단계에서 끊긴 참가자의 자리와 방장 역할을 30초 동안 유지한다. 30초는 서버가 끊김을 알아챈 때가 아니라 그 휴대폰에서 마지막으로 무엇이든(메시지 또는 브라우저가 화면이 꺼져도 자동으로 보내는 ping 응답) 받은 때부터 센다. 서버는 5초마다 ping을 보내고, 10초 동안 아무것도 받지 못한 연결은 끊긴 것으로 처리한다. 방장의 초기화(대기실로 되돌리기)는 게임이 끝난(ENDED) 뒤에만 받는다. 방장이 시작을 누르는 순간 끊긴 사람도 명단에 들어가고, 복귀하면 참가자로 이어서 한다. 방장 역할은 방장 자리가 만료될 때만 다음 사람에게 넘어가며, 방을 만든 브라우저(같은 보관함 식별자)가 돌아오면 다시 방장이 된다. 직접 나가기(LEAVE_ROOM)만 즉시 자리를 비운다.

정체된 연결에 갇혀 있던 복귀·재입장 요청이 뒤늦게 도착해도, 이미 더 새로운 연결이 그 자리를 쓰고 있으면 거절한다. 예전에는 늦은 요청이 새 연결을 4001로 끊어 휴대폰이 로비로 쫓겨났다. 다른 탭이 나중에 접속해 자리를 가져가는 경우(더 새로운 연결)는 그대로 허용한다.

입장·끊김·복귀처럼 인원만 바뀌는 방 상태는 0.25초 안의 변화를 한 번으로 묶어 보내고, 방 목록은 로비 화면에만 0.25초 단위로 보낸다. 재시작 뒤 수십 명이 한꺼번에 복귀할 때 느린 휴대폰에 같은 상태가 수십 번 쌓이지 않게 하기 위해서다. 종료 신호를 받은 서버는 마지막 저장 뒤 메시지와 단계 타이머를 멈춰, 저장 뒤 0.4초 동안 받은 답이 사라지거나 결과가 두 번 기록되지 않게 한다.

예약은 다음 경로로 정리한다.

- 만료 타이머가 기한 직전에 실행되면 남은 시간만큼 다시 예약한다.
- 별도 1초 점검이 만료된 예약을 정리한다. 타이머 유실에도 대응한다.
- 대기실 초기화 시 이미 끊긴 연결은 즉시 제거한다.
- 입장·복귀·방 목록 요청 전에도 만료된 예약을 정리한다.
- 같은 브라우저 보관함 식별자로 재입장하면 기존 자리가 유효할 때 그 플레이어를 복원한다. 참가자가 중복되거나 관전자로 바뀌지 않는다.
- 이전 연결의 늦은 close/error가 교체된 새 연결의 플레이어를 제거하지 못하게 한다.

진행 중인 방은 2초마다, 그리고 PM2의 SIGINT/SIGTERM 종료 직전에 `live-rooms.json`(퀴즈 보관함과 같은 폴더)에 원자적으로 저장한다. 새 프로세스는 10분 이내 저장본을 읽어 같은 방 ID·라운드 ID·제출 답안·역할·복귀 토큰으로 복원하고, 재시작 때문에 끊긴 자리는 30초 동안 예약한다. 재시작 전에 이미 끊겨 있던 자리는 원래 기한(끊긴 시각부터 30초)을 그대로 쓰며, 재시작이 이를 늘리지 않는다. 서버가 내려가 있는 사이 기한이 지났으면 복원 직후 만료된다. 진행 중이던 단계는 남은 시간에 5초를 더해 이어 간다. 봇 테스트 방은 시작할 때 새로 만들어지므로 저장하지 않는다.

단계 전환은 직렬화 가능한 예약 동작(`next`·`open`·`judge`·`break`·`finish`·`ended` 등) 하나로만 관리한다. 타이머가 유실되거나 콜백이 예외로 끝나도 마감 2초 후 서버 점검이 같은 동작을 실행한다. 예약이 없으면 현재 단계에서 할 동작을 추론한다. 동작이 예외로 실패해도 게임을 자동으로 끝내지 않는다. 실패한 동작이 바꾼 게임 상태(단계·문제 번호·생존·답안·위치·추첨 결과 등)를 실행 직전으로 되돌린 뒤 같은 동작을 2초 뒤 다시 시도한다. 반쯤 바뀐 상태에서 다시 실행해 문제를 건너뛰거나 판정을 두 번 적용하는 일이 없다. 단, 이미 뽑힌 추첨은 누군가 봤을 수 있으므로 되돌리지 않고 그대로 확정한다. 그래서 일시적인 오류는 스스로 풀리고 버그는 수정 배포 후 복원된 방에서 이어 간다. 판정 단계 밖에서 판정이 호출돼도 예약된 다음 동작을 지우지 않는다. 단계 복구는 서버 시간을 임의로 연장하거나 정답을 클라이언트 기준으로 판정하는 기능이 아니다.

처리되지 않은 예외는 로그만 남기고 다른 방을 계속 진행한다. 1분 안에 20번 넘게 반복되면 방을 저장한 뒤 PM2가 새 프로세스로 다시 띄우게 한다.

재현 검증: `node scripts/audit-connection-recovery.cjs`는 격리 포트 3147에서 PC·모바일 화면과 43개 WebSocket 클라이언트(총 45명)를 사용한다. 전환 패킷 누락과 rAF 정지, 수동 복구, 응답 없는 연결, 늦은 close, 중복 창 교체, 만료 타이머 유실, 만료 후 관전 입장, 42개 동시 재접속을 검증한다. 실제 폰 45대의 무선망이나 발생 당시의 운영 로그를 재현한 것은 아니다.

운영 시나리오 검증: `npm run test:scenarios`(`scripts/audit-scenarios.cjs`)는 격리 서버에서 실제 타이머와 실제 WebSocket으로 38개 상황을 동시에 돌린다. 문제 유형별 진행과 종료·당첨 규칙(목표 이하 즉시 종료, 전원 오답, 최종 추첨, 준우승 추첨, 패자부활전과 건너뛰기, 소수결 동수, 레이스, 쉬는 시간 0초, 초기화 규칙)을 본다. 답안 경계(마지막 답, 재전송, 마감 직후, 이전 문제 답, 관전자, 수정 중)도 확인한다. 연결(문제·쉬는 시간·대기실 중 끊김과 복귀, 조용한 끊김 10초 감지와 마지막 신호 기준 30초, 만료 후 관전, 방장 유지·승계·복귀, 두 탭, 다른 방 입장, 늦은 옛 복귀 요청, 정원 50명, 40명 동시 복귀)과 폭주(깨진 메시지·5MB 초과, 메시지 3000개, 이동 60개)도 다룬다. 장애 주입(판정·다음 문제 전환 직후 오류, 단계 타이머 유실, 서버 강제 종료 뒤 복원)까지 포함한다. 배포 전에 한 번 돌린다(약 40초).

운영 로그의 `CONNECTION_CLOSED`(접속 유지 초·흐름 제어로 건너뛴 틱 수 포함), `SESSION_RESTORED`, `SESSION_EXPIRED`, `LIVE_ROOMS_RESTORED`, `ROOM_PHASE_OVERDUE`, `ROOM_PHASE_FAILED`에는 방·사용자 식별자와 종료 코드가 남는다. 비밀번호·세션 토큰·답안은 기록하지 않는다.

## 진단 로그

서버의 모든 로그 줄은 `2026-10-27 15:42:01.123 KST`처럼 한국 시각으로 시작한다. PM2 설정과 무관하게 앱이 직접 찍으므로 로그 파일만으로 같은 초에 끊긴 사람들을 맞춰 볼 수 있다.

휴대폰은 아래 상황을 기록해 두었다가 연결이 살아나면 5초 간격으로 묶어 보내고, 서버는 한 건당 한 줄의 `CLIENT_DIAG`로 남긴다. 보내지 못한 기록은 새로고침해도 남아 다음 접속에서 보낸다.

| reason | 뜻 |
|---|---|
| `stall` | 3초 동안 어떤 패킷도 오지 않아 연결을 교체함 |
| `state-timeout` | 마감이 지난 뒤 요청한 게임 상태가 2.5초 안에 오지 않음 |
| `connect-timeout` | 새 연결이 5초(직접 주소는 3초) 안에 열리지 않음 |
| `wake-probe-timeout` | 화면 복귀·네트워크 변경 직후 확인 핑에 2.5초 안에 답이 없음 |
| `socket-closed` | 연결이 닫힘(`code`: 1006 망 끊김, 1001 페이지 이탈·정리, 1012 서버 재시작, 4001 다른 창) |
| `resumed` / `rejoined` / `reconnected` | 같은 자리 복귀 / 자리 재입장 / 로비 재연결. `outageMs`는 끊김부터 복귀까지 걸린 시간 |
| `resume-rejected` | 복귀 거절(`room-gone`: 방 없음, `room-exists`: 자리 만료) |
| `recover` | 연결 복구 실행(`button`: 사용자가 누름, `session-missing`·`world-error`: 자동) |
| `main-thread-blocked` | 화면 스레드가 `blockedMs` 동안 멈춤. 기기 성능 부족의 직접 증거 |
| `returned` | 다른 앱에 갔다가 `awayMs` 만에 돌아옴 |
| `page-reloaded` | 게임 중 새로고침하거나 다시 열어 `awayMs` 만에 돌아옴 |
| `answer-unconfirmed` | 낸 답이 서버 확인 없이 문제가 끝남(`detail`: `SUBMIT_SHORT`/`SUBMIT_MULTIPLE`). 억울한 탈락 의심 |
| `join-timeout` | 방 화면에서 열린 연결이 4초 동안 입장 확인을 못 받아 다시 연결함 |
| `render-error` / `world-error` / `js-error` | 화면 갱신·월드 갱신·스크립트 오류(`detail`에 메시지) |
| `direct-failed` / `direct-probe` / `direct-switch` | 직접 주소 연결 실패(화면이 켜져 있을 때만) / Cloudflare로 붙은 뒤 직접 주소 확인 결과 / 직접 주소로 되돌림([direct-connection.md](direct-connection.md)) |

모든 항목에는 그 순간의 `gapMs`(마지막 패킷 이후 시간), `rttMs`·`minRttMs`(왕복 지연), `fps`, `maxFrameMs`(직전 보고 이후 가장 긴 프레임), `state`, `hidden`, `attempts`(재접속 시도), `net`(브라우저가 알려 주는 망 종류), `path`(직접 주소가 켜져 있을 때 `direct`/`cf`), `device`(예: `android/kakaotalk`, `ios/safari`), `ago`(기기 시계로 잰 경과 시간)가 함께 남는다. 연결당 5초에 한 묶음, 묶음당 10건까지만 받고 알려진 필드만 길이를 제한해 기록한다.
