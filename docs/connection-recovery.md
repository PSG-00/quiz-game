# 연결 복구와 예약 자리 정리

게임 화면과 로비에 `연결 복구` 버튼을 제공한다. 정상 연결에서는 먼저 해당 소켓으로 최신 ROOM_STATE와 전체 WORLD_TICK을 요청한다. 2.5초 안에 복구 응답이 없을 때만 연결을 교체하며, 새 연결의 재입장이 확정될 때까지 기존 연결을 먼저 닫지 않는다. 이 순서로 대기실 단독 사용자의 방이 복구 중 삭제되는 문제를 막는다. 복귀 토큰이 거절돼도 바로 로비로 보내지 않고 같은 브라우저 식별자로 기존 자리를 찾는 JOIN_ROOM을 한 번 시도한다. 실제 예약이 만료된 경우에는 관전 자격만 부여한다. 최신 상태에는 요청자 자신의 제출 답안만 포함한다. 이미 내려진 탈락 판정을 되돌리거나 30초 만료 이후 참가 자격을 새로 부여하지 않는다.

자동 동기화는 렌더링 루프에서 분리한 1초 간격 점검으로 실행한다. 5초 간격 애플리케이션 ping으로 단계 버전을 확인하고, 응답이 12초 이상 없는 OPEN 연결 또는 10초 이상 열리지 않는 연결은 새로 만든다. 재접속에는 지연과 임의 분산을 두며 오래된 소켓의 이벤트는 무시한다. 다른 창으로 연결이 넘어가 종료된 창은 자동 접속 경쟁을 반복하지 않는다. 전체 상태가 없는 부분 패킷은 불완전한 캐릭터로 만들지 않고 다시 전체 상태를 요청한다.

서버는 30초 복귀 유예를 유지하되 다음 경로로 예약을 정리한다.

- 만료 타이머가 기한 직전에 실행되면 남은 시간만큼 다시 예약한다.
- 별도 1초 점검이 만료된 예약을 정리한다. 타이머 유실에도 대응한다.
- 대기실 초기화 시 이미 끊긴 연결은 즉시 제거한다.
- 입장·복귀·방 목록 요청 전에도 만료된 예약을 정리한다.
- 같은 브라우저 보관함 식별자로 재입장하면 기존 자리가 유효할 때 그 플레이어를 복원한다. 참가자가 중복되거나 관전자로 바뀌지 않는다.
- 이전 연결의 늦은 close/error가 교체된 새 연결의 플레이어를 제거하지 못하게 한다.

쉬는 시간 전환 타이머가 실제로 유실된 경우에도 마감 2초 후 서버 점검이 다음 문제를 시작한다. 단계 복구는 서버 시간을 연장하거나 정답을 클라이언트 기준으로 판정하는 기능이 아니다.

재현 검증: `node scripts/audit-connection-recovery.cjs`는 격리 포트 3147에서 PC·모바일 화면과 43개 WebSocket 클라이언트(총 45명)를 사용한다. 전환 패킷 누락과 rAF 정지, 수동 복구, 응답 없는 연결, 늦은 close, 중복 창 교체, 만료 타이머 유실, 만료 후 관전 입장, 42개 동시 재접속을 검증한다. 실제 폰 45대의 무선망이나 발생 당시의 운영 로그를 재현한 것은 아니다.

운영 로그의 `CONNECTION_CLOSED`, `SESSION_RESTORED`, `SESSION_EXPIRED`에는 방·사용자 식별자와 종료 코드가 남는다. 비밀번호·세션 토큰·답안은 기록하지 않는다.
