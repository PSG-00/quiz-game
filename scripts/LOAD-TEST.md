# 100명 부하 테스트

`npm run test:100`으로 현재 코드를 사용하는 3105 서버와 봇 100명을 실행합니다. 다른 포트는 PowerShell에서 `$env:PORT='3110'; npm run test:100`처럼 지정합니다. 이미 해당 포트가 사용 중이면 기존 프로세스를 건드리지 않고 오류로 종료합니다.

방 목록의 **[테스트] 봇 100명 · 이동/소수결**에 입장합니다. 처음 들어온 실제 사용자가 방장이 되므로 시작·재시작할 수 있습니다. 봇은 여섯 아바타로 계속 이동하고, 주관식/버튼 객관식에는 예시 답을 제출합니다. OX·소수결·소수결 부활전·네 구역 이동 객관식·주관식이 포함됩니다.

일반 방의 최대 인원은 100명입니다. 이 실행의 내부 테스트 방만 **봇 100명 + 실제 사용자 1명 = 101명**을 허용합니다. 웹 클라이언트가 이 예외를 요청하는 기능은 없으며, `npm start`에서는 테스트 방이나 봇이 생성되지 않습니다. 테스트 방의 게임은 저장 퀴즈 보관함에 저장하지 않습니다. 실행 중인 서버의 저장 정책은 기존 `server/index.js`와 같습니다.

100개의 실제 WebSocket 연결이 서버의 입장·이동·판정·방송 코드를 통과합니다. 동일한 WORLD_TICK 메시지를 받아도 운전 스크립트는 한 연결에서만 JSON을 해석하고 공유하여, 이 PC에서 100개 JSON 파서를 돌리는 추가 부하를 줄입니다. 이는 **100개 기기/브라우저의 실제 렌더링 성능 테스트가 아닙니다.** 브라우저 한 개에서 모든 캐릭터를 그리는 비용과 서버의 100개 연결 처리·송수신을 테스트합니다.

`artifacts/bot-load-test.json`에 PID·방 ID·접속 수·누적 입력·수신 바이트/초가 기록됩니다. 표시된 바이트는 100개 로컬 소켓 수신 합계이며 실제 인터넷 회선 처리량이 아닙니다. 터미널에서 실행했다면 Ctrl+C로 서버와 봇을 함께 종료합니다. 숨김 실행은 기록된 테스트 PID의 **명령줄이 이 스크립트인지 확인한 뒤** 그 프로세스만 종료합니다. 그러면 테스트 방도 닫힙니다.

소수결은 준비·진행 중 좌우 인원수와 소수 구역을 안내하지 않습니다. 캐릭터는 계속 보이며, 판정이 끝난 뒤 결과 화면에서 최종 좌우 인원수와 승리 구역을 공개합니다. 접속자가 화면의 캐릭터 위치를 직접 세거나 네트워크 좌표를 분석하는 것까지 막는 기능은 아닙니다.

PC·모바일 모두 `저사양 모드`를 켜면 본인만 정밀 3D로 그리고, 다른 사람은
둥근 머리와 역원뿔 몸통이 떨어진 간단한 SD로 표시합니다. 머리·몸·눈을
InstancedMesh 세 개로 그리며 사람당 264삼각형입니다. 닉네임·상태판·채팅은
유지하며 탈락자는 기존 유령으로 전환합니다. 모드를 끄면 정밀 아바타를
프레임당 최대 두 개씩 복원합니다. 생성했던 모델은 재사용하고, 표시하지
않는 모델은 장면에서 분리하여 숨겨진 뼈대의 행렬 계산도 피합니다.
기본은 꺼짐이며 설정은 해당 브라우저에 저장합니다.

모바일 60FPS 제한을 제거하고 화면 주사율에 맞춰 최대 144FPS를 허용합니다.
144Hz 기기에서도 브라우저·발열·실제 GPU 부하에 따라 달라집니다.
모바일 실시간 그림자와 안티앨리어싱은 끄되
렌더링 픽셀 비율은 최대 2, 초기 화면 기준 약 160만 픽셀 예산입니다.
`QuizPerformance.snapshot()`으로 FPS·그리기 횟수·삼각형 수·저사양 모드·
상세/경량 캐릭터 수·캐시 수·월드 수신 간격을 확인합니다. 자동 검증은
`artifacts/low-spec-toggle-check.cjs`로 실행합니다. PC 모바일 에뮬레이션의
결과가 실제 휴대폰 성능을 보장하지는 않습니다.

PC의 MSAA는 같은 해상도의 FXAA 화면 패스로 대체했습니다. 원격
발밑 그림자와 상태 카드도 공유 배치로 그리며 원격 DOM 위치는 최대
30Hz로 갱신합니다. `snapshot().antialias`는 PC `fxaa`, 모바일 `direct`이며
`decorations`에 실제 활성 그림자/카드 배치 수가 나옵니다. FXAA의 1회
추가 화면 그리기는 통계에 포함합니다.

`artifacts/pc-render-profile.cjs`는 실제 방에 입장하지 않고 같은 100명
합성 이동 장면에서 이전 MSAA·개별 장식과 새 경로를 비교합니다.
실제 노트북 GPU를 쓰지만 다른 앱/GPU 작업의 영향을 받으므로 실제 폰
측정이나 보장된 FPS로 해석하지 않습니다. 측정 중 다른 브라우저
검증을 동시에 실행하지 않습니다. `fxaa-check.cjs`는 색상·리사이즈·DPR,
`crowd-decorations-check.cjs`는 기존 장식과의 픽셀 일치 및 배치 수를 검증합니다.

정밀 모드는 원격 캐릭터를 뼈대 애니메이션 텍스처와 모델별 인스턴싱으로
그립니다. 본인은 기존 모델을 유지하고, 화면 밖·유령·저사양 캐릭터는
정밀 배치에서 제외합니다. `QuizPerformance.snapshot()`의 `instancing`에
모델별 인원·배치 수·텍스처 크기가 나옵니다. `frameLimit`는 설정 상한,
`fps`는 실제 렌더 횟수, `frameP95Ms`는 최근 프레임 간격의 95백분위,
`browserCallbackHz`는 실제 브라우저 콜백 빈도입니다. 화면 주사율의
직접 측정값으로 해석하지 않습니다. 게임 규칙 창에서도 현재 FPS를 봅니다.

`artifacts/instanced-avatar-check.cjs`는 3106의 격리된 100봇 서버에서
실제 연결과 독립 동작·유령·부활·저사양 전환·슬롯 반환을 검증합니다.
라이브 접속을 확인한 뒤 위치 업데이트만 고정하여 동일한 카메라와
가시 인원 배치로 두 렌더러의 5초 평균 FPS를 비교합니다. PC의 모바일
뷰포트 에뮬레이션이며 실제 휴대폰 측정이 아닙니다.
`artifacts/instanced-visual-check.cjs`는 여섯 캐릭터의 정면·측면·후면에서
기존 실시간 모델과 배칭 모델의 픽셀 차이를 비교합니다.

일반 라운드 전환은 현재 무대 좌표를 유지하고, 같은 역할인 본인 좌표를 과거 서버 스냅샷으로 덮어쓰지 않습니다. 시작 카운트다운 뒤 추가 준비 단계를 없앴으며, 상단 문제 영역의 높이가 달라져도 같은 화면 크기 안에서는 카메라 배율과 하단 기준 구도를 유지합니다. 탈락·부활에 따른 층 이동은 계속 적용합니다.
