# 50명·100명 통신 부하 검증 (2026-10-25)

## 공개 도메인 변경 전 결과

실제 `https://quiz.rescene.online`을 통해 측정했다. 각 연결은 기존 100봇 스크립트와 같은 사인/코사인 이동식을 사용해 100ms마다 MOVE를 전송했다. 운영 정원 50명은 유지하고 100명은 50명씩 두 검증 방에 나눴다. 저장 퀴즈와 기존 방은 수정하지 않고 검증 방은 연결 종료로 정리했다.

| 접속 | 측정 | 입장 성공 | HTTP/업그레이드 429 | 중도 연결 종료 | 전체 월드 수신량 | 이동 반영 지연 P95 |
| --- | --- | --- | --- | --- | --- | --- |
| 50명 / 1방 | 30초 | 50/50 | 0 | 0 | 142.55MB | 252.1ms |
| 100명 / 2방 | 30초 | 100/100 | 0 | 0 | 286.04MB | 265.7ms |

동시 HTTP 요청도 보냈다: 사용자 수만큼 HTML, 사용자당 app.js·style.css·모델 파일 64KiB 범위 요청, 마지막 모델 표본 1회. 50명에서 200 응답 150개·206 응답 51개, 100명에서 200 응답 300개·206 응답 101개였으며 최종 측정의 404·429·요청 실패는 없었다. 최대 HTTP 동시성은 200으로 제한했다. **모든 사용자에게 모든 3D 모델을 전체 다운로드시키는 콜드 스타트 테스트는 아니다.**

처음 50명 탐침에서는 아직 배포되지 않은 LOD 파일 경로를 요청해 404가 생겼다. 이후 양쪽에 존재하는 공통 자원으로 목록을 고정해 50명 시험을 다시 실행했고 위 표에는 재측정 결과만 사용했다.

원본: `artifacts/network-before-50.json`, `artifacts/network-before-100.json`.

## 구현 및 격리 서버 검증

- 입장 시 전체 스냅샷, 이후 변경된 좌표·상태 필드만 WORLD_DELTA로 방송한다. 입퇴장·역할·제출 상태도 병합한다. 5초마다 전체 상태를 보내고, 느린 연결에는 오래된 위치를 누적하지 않고 큐가 비면 전체 상태로 복구한다.
- 클라이언트가 명시적으로 worldDelta를 요청한 연결에만 새 방식을 사용한다. 이전 클라이언트는 기존 전체 WORLD_TICK을 받는다.
- 모델·이미지·LOD는 1시간 공개 캐시, vendor 코드는 1일 캐시, 게임 코드는 ETag로 유효성 검사한다. HTML·서비스 워커·API에는 no-store를 적용한다. 서비스 워커는 API와 다른 출처를 캐싱하지 않는다. 이는 브라우저 캐싱이며 Cloudflare CDN HIT는 실제 배포 후 별도 확인해야 한다.

저장 데이터를 사용하지 않는 로컬 3120 격리 서버에서 같은 30초 시험을 실행했다.

| 접속 | 입장 성공 | HTTP/업그레이드 429 | 중도 종료 | 전체 월드 수신량 | 실제 MOVE 수 |
| --- | --- | --- | --- | --- | --- |
| 50명 | 50/50 | 0 | 0 | 33.22MB | 13,650 |
| 100명 | 100/100 | 0 | 0 | 65.58MB | 27,300 |

**이 표는 공개 도메인의 적용 후 결과가 아니다.** 서버·망·타이머 실행 횟수가 달라 공개 서버의 지연 및 FPS와 직접 비교하지 않는다. 공개 서버의 MOVE 수는 각각 14,800·29,700건이었다. 확정적인 전후 비교는 GCP 운영 서버에 배포한 뒤 동일 도메인에서 재측정해야 한다.

원본: `artifacts/network-after-local-50.json`, `artifacts/network-after-local-100.json`.

## 실행

```powershell
node scripts/network-load-test.cjs --url=https://quiz.rescene.online --clients=50 --seconds=30 --label=after
node scripts/network-load-test.cjs --url=https://quiz.rescene.online --clients=100 --seconds=30 --label=after
```

이 시험은 WebSocket·HTTP 통신 부하다. 실제 폰/브라우저 100대의 3D 렌더링이나 장시간 안정성을 증명하지 않는다. 30초 동안 429가 없었다는 관찰로 앞으로 429 확률이 0이라고 결론 내리지 않는다.

배포 경로는 `.github/workflows/deploy.yml`의 main/master 푸시 → GCP 자체 실행기 → PM2 재시작이다. 사용자 승인 후 541f5d7을 main에 반영했고, 공개 앱 해시(줄바꿈 제외)·worldDelta 기능·모델 캐시 헤더로 GCP 적용을 확인했다. 기존 로컬 LOD·정원 50명·관전석 크기 조정도 함께 반영됐다.

## 동일 공개 도메인 적용 후 재시험

| 접속 | 입장 성공 | HTTP/업그레이드 429 | 중도 종료 | 변경 전 월드 수신량 | 적용 후 월드 수신량 | 수신량 감소 |
| --- | --- | --- | --- | --- | --- | --- |
| 50명 / 1방 / 30초 | 50/50 | 0 | 0 | 142.55MB | 35.17MB | 약 75.3% |
| 100명 / 2방 / 30초 | 100/100 | 0 | 0 | 286.04MB | 70.52MB | 약 75.3% |

이 표의 변경 전·적용 후는 **모두 같은 공개 도메인**의 결과다. 적용 후에도 50명 HTTP 200×150·206×51, 100명 HTTP 200×300·206×101이었고 요청 실패가 없었다. 적용 후 실제 MOVE 수는 14,450·29,100건으로 변경 전 14,800·29,700건보다 조금 적다. MOVE당 바이트로 나눠도 약 75% 감소다. 총 수신 속도는 각각 약 4.75→1.17MB/s, 9.53→2.35MB/s였다.

이동 반영 지연 P95는 50명 252.1→260.5ms, 100명 265.7→270.5ms였다. 지연 개선은 확인되지 않았고 네트워크·실행 변동 범위의 차이를 성능 향상으로 해석하지 않는다. 이번 성과는 주로 전송량 감소이며 FPS 향상을 측정한 시험이 아니다.

공개 주소의 실제 Chrome 캐시 검증에서 4,510,580바이트 모델은 첫 요청 전송 4,510,880바이트(헤더 포함), 두 번째 0바이트였다. API는 no-store이며 서비스 워커 저장 대상에서도 제외된다. 모델의 CF-Cache-Status는 DYNAMIC이므로 **Cloudflare 공유 CDN 캐시 HIT로 주장하지 않는다.** 브라우저 캐시 재사용을 확인한 것이다.

추가 검증: 자동 테스트 109개 통과. 실제 PC·모바일 화면에서 입퇴장 중 주관식 입력과 포커스 유지, 델타 이동, 참가자 제거, 유령 전환 및 75% 크기를 확인했다. 구 클라이언트·전체 스냅샷 복구와 느린 연결 큐 보호도 테스트했다.

배포 설정에서는 전체 작업 폴더 청소를 끄지 않고, 기존 data만 비공개 임시 폴더로 보존한 뒤 깨끗한 체크아웃에 복원하는 절차를 추가했다. 쓰기 경합을 피하도록 복사 전 기존 PM2 앱을 중지한다. 가짜 데이터로 데이터 바이트 보존·오래된 코드 미복원·신규 코드 유지를 검증했다.
