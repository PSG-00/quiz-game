# 게임 동시성·오류 점검 — 2026-10-26

> 아래는 수정 전 최초 점검 기록이다. 이 문서의 미해결 항목에 대한 후속 구현·현재 정책·검증 결과는 [참가 자격·재접속 수정 결과](session-policy.md)를 기준으로 확인한다.

현재 로컬 코드 기준. 운영 서버·3105 테스트 방에는 재현 요청을 보내지 않았으며, 아래 수정은 **운영 미배포**다. 격리 서버는 저장 기능과 자동 테스트 봇을 끄고 실행했다.

## 사용자가 제시한 세 상황

| 상황 | 확인 결과 | 판단 |
| --- | --- | --- |
| 진행 중 연결 종료 후 같은 브라우저로 복귀 | **문제 재현**. 새 참가자 ID를 받고 유령으로 입장. 생존·위치·이미 제출한 답을 잃음 | 일시적 연결 장애와 명시적 퇴장을 구분하는 복구 절차 필요 |

### 권장 재접속 정책 — 아직 구현하지 않음

- 명시적으로 ‘로비로’ 나가기: 즉시 퇴장. 우연한 소켓 종료: 예를 들어 **30초간 자리와 게임 상태를 보존**하는 방식을 권장한다.
- 닉네임 대신 서버가 검증하는 재접속 토큰으로 본인을 확인한다. 퀴즈 보관함 키는 현재 게임 복구 토큰이 아니다.
- 유예 중에도 문제 시간과 판정은 계속 진행한다. 끊기기 전 마지막 서버 좌표·제출 답안으로 판정하고, 그동안 탈락했다면 복귀 후에도 유령이어야 한다.
- 예약된 자리는 50명 정원에 포함한다. 중복 탭이 자리를 두 개 차지하거나 복귀 때문에 51명이 되면 안 된다.
- 접속 중인 다음 사람에게 방장을 넘기고, 돌아온 이전 방장이 자동으로 권한을 뺏지 않도록 한다.
- 마지막 사용자도 일시 단절이면 유예 후 방 정리, 명시 퇴장이면 즉시 정리하는 구분이 필요하다. 서버 재시작 후 복구는 별도 영속화 없이는 지원되지 않는다.

### 판정 불일치 재현

1. 브라우저 예측 좌표 `x=-0.001` → 머리 위 표시 **O**.
2. 서버가 소수 둘째 자리로 반올림 → `x=0` → **X**. 정답 O 판정에서 해당 플레이어 탈락.
3. 별도 시험에서는 서버 좌표 X 상태에서 브라우저를 O로 이동시키고 발신 MOVE를 200ms 지연시켰다. 서버 수신 전 마감 판정 시 화면 O / 서버 X로 탈락했다.

PC Chromium 1280×800과 모바일 화면 재현 390×844에서 두 경로를 확인했다. 모바일 화면 시험은 PC Chromium의 화면·터치 설정이며 실물 폰 네트워크 시험은 아니다. 이동은 좌표를 제어한 재현 시험으로, 발생 빈도를 측정한 결과는 아니다. 캐릭터의 보간된 표시 위치와 예측 좌표도 별개다.

우선 공통 좌표 정밀도·경계 함수를 사용해야 한다. 서버가 확정한 구역과 아직 전송 중인 구역을 구분해 보여 주고, 이동 순번·확인 응답과 왕복 지연을 고려한 시계 동기화가 필요하다. 클라이언트가 주장하는 ‘마지막 정답 구역’을 그대로 믿는 방식은 피한다. 지연이 무한한 환경까지 화면과 판정을 완전히 일치시킨다는 보장은 할 수 없다.

## 발견 즉시 보완한 로컬 버그

| ID | 수정 전 실제 재현 | 로컬 보완 | 재검증 |
| --- | --- | --- | --- |

| SESSION-02 | 혼자 있는 방에 같은 소유 키의 새 탭으로 입장하면 방이 관리자 목록에서 사라짐 | 교체 중인 대상 방은 빈 방 정리에서 보존 | 새 탭 입장 후 방 유지 |

## 남은 우선 수정 항목

| 우선순위 | 항목 | 근거 | 후속 작업 |
| --- | --- | --- | --- |
| 높음 | SESSION-01 재접속 상태 소실 | 실제 연결 종료·같은 보관함 키 재접속으로 확인 | 검증 가능한 복구 토큰·유예 자리·만료 처리 도입 |
| 높음 | O/X 경계 표시 불일치 | 실제 브라우저, 위 재현값 | 공통 반올림·경계 규칙 적용 |
| 높음 | 마감 직전 미확인 이동 표시 | 실제 브라우저, 발신 200ms 지연 | 확정 구역 표시·이동 순번/ACK·시계 보정 |
| 높음 | ANSWER-01 이전 문제 답안이 다음 문제에 접수 | 0번 문제 답안 `서울`을 1번 문제 `부산` 진행 중 전달하니 제출됨 | 제출·수정 중 상태·ACK를 gameId와 문제 식별자에 묶고 불일치 거절 |
| 보통 | 이동 속도·워프 검증 부재 | 코드 검토: 경계·유한값·마감은 검사하지만 이동 거리/시간은 검사하지 않음 | 최대 속도와 보정 정책 설계 후 악성 입력 재현 시험 |
| 보통 | MOVE/CHAT 요청 빈도 제한 부재 | 코드 검토: 개별 메시지 경로에 속도 제한 없음 | 정상 50명 트래픽을 해치지 않는 제한·초과 처리 시험 |

ANSWER-01은 ‘마감이 지난 답안을 받는다’는 뜻과 다르다. **현재 문제의 마감 이후 요청은 거절하지만, 이전 문제의 요청이 다음 문제 시간 안에 들어오면 구분하지 못한다.** 같은 WebSocket은 순서를 보존하므로 모든 정상 요청에서 발생한다는 뜻은 아니다. 지연·재전송·문제 전환에 대한 요청 식별이 없는 문제가 실제 서버 경로에서 확인됐다.

## 실행·증거

- `npm test`: **114개 통과**. 실제 WebSocket 회귀 테스트가 포함된다.
- `node scripts/audit-game-concurrency.cjs`: 격리 서버 포트 3132, 상태 관찰 11개 중 9개 통과 / 2개 미해결. 기존에 없던 복구 기능의 미구현도 FAIL로 기록한다.
- `node scripts/audit-client-judgement.cjs`: 포트 3133, PC 화면 재현.
- PowerShell: `$env:AUDIT_PORT='3134'; $env:AUDIT_MOBILE='1'; node scripts/audit-client-judgement.cjs`: 모바일 화면 재현.
- `PLAYWRIGHT_PATH` 환경 변수로 브라우저 시험의 Playwright 모듈 경로를 바꿀 수 있다. 기본값은 이 PC의 번들 런타임 경로다.
- `scripts/lib/auditServer.cjs`의 제어는 fork IPC 전용이다. 운영 HTTP API·운영 진입점에는 등록하지 않는다.
- 진단 스크립트는 알려진 미해결 항목을 FAIL로 기록하면서 정상 종료할 수 있다. **종료 코드 0이 게임의 모든 검사를 통과했다는 뜻은 아니다.** 회귀 테스트는 이번에 보완한 항목과 통과해야 할 항목을 별도로 assert한다.

생성 증거: `artifacts/game-concurrency-audit-final.json`, `artifacts/game-concurrency-audit-regression.json`, `artifacts/client-judgement-audit.json`, `artifacts/client-judgement-audit-mobile.json`. 브라우저 캡처는 `artifacts/audit-rounding-before*.png`, `artifacts/audit-rounding-after*.png`다. artifacts는 로컬 생성물이며 Git에 포함하지 않는다.

이번 결과는 운영 GCP·Cloudflare의 망 장애나 50명 실물 폰 동시 시험 결과를 대신하지 않는다. 3105·공개 테스트 봇과 저장 퀴즈는 그대로 유지했다.
