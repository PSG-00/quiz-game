# 모바일 입력창 키보드 대응

2026-10-26: 주관식·채팅에 포커스가 생기면 VisualViewport의 높이와 offsetTop으로 가려진 하단 영역을 계산하여 고정 컨트롤만 올린다. resize·scroll 이벤트와 포커스 후 900ms 동안의 짧은 확인으로 키보드 열림 애니메이션을 반영한다. 값이 바뀔 때만 CSS/카메라 레이아웃 갱신을 요청하며, 맵 고정 처리는 유지한다. 키보드가 닫히거나 포커스가 해제되면 하단 보정을 제거한다.

검증: `node scripts/audit-input-viewport.cjs`. 모바일 화면 Chromium에서 VisualViewport 속성으로 키보드가 덮는 영역을 재현한다. (1) 첫 글자 입력 전 키보드 resize (2) offsetTop 변경/scroll (3) resize 알림 없이 포커스 직후 높이 변경 (4) 채팅 키보드 (5) layout viewport도 같이 줄어드는 방식의 중복 상승 방지를 검사했다. 모두 input 이벤트 0회, 빈 입력값 상태에서 입력창이 보이는 영역 안에 있고 종료 후 보정 0으로 돌아옴을 확인했다. overlay 방식에서 맵 높이가 유지됨도 확인했다.

실제 Android/iOS 키보드나 IME 자체를 실행한 검사는 아니므로 기기별 키보드 애니메이션 체감은 실기기에서 확인해야 한다. 기존 모바일 답안·재접속·관전 브라우저 회귀 검사도 통과했다.
