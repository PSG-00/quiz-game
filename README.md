# 모두의 OX 퀴즈쇼

모바일 세로 화면을 우선한 Three.js + Express + WebSocket 퀴즈 게임입니다. `ox/outputs`의 명세 4개와 시안 이미지 5개를 참고했습니다.

## 실행

```powershell
npm install
npm start
```

기본 주소는 http://localhost:3000 입니다. `$env:PORT='3105'`로 포트를 변경합니다. Three.js와 Pretendard는 CDN을 사용합니다.

## 내 퀴즈와 게임 방

방 만들기 화면 맨 위의 **퀴즈 저장**은 현재 내용을 서버의 `data/quizzes.json`에 보관합니다. 문제를 다 작성하지 않아도 임시 저장할 수 있습니다. **퀴즈 불러오기**에서 보관한 퀴즈를 선택해 이어서 작성합니다. **퀴즈 저장**은 제목을 기준으로 처리합니다. 다른 제목은 별도 퀴즈로 바로 저장합니다. 같은 제목의 내용·설정이 달라졌을 때만 덮어쓰기 확인창을 표시하고, 내용까지 같으면 기존 저장을 유지합니다. 확인을 취소하면 저장한 원본과 작성 중인 내용을 그대로 유지합니다. 서버에서 같은 사용자의 제목을 비교하며 확인 대기 중 다른 탭에서 바뀌면 다시 확인합니다. 보관함의 **새 퀴즈 만들기**로 여러 퀴즈를 각각 저장할 수 있습니다. 목록의 **삭제**를 누르고 확인하면 본인의 저장 퀴즈를 제거합니다. 삭제는 이미 열린 게임과 편집 중인 내용을 유지하며 서버 재시작 뒤에도 다시 나타나지 않습니다. 잘못 불러오거나 문제를 삭제했을 때 편집기 오른쪽의 되돌리기를 사용할 수 있습니다.

제목과 당첨 목표 인원은 접힌 메뉴 없이 항상 펼쳐 표시합니다. 문제 유형은 OX·객관식·주관식 순서이며 O/X 정답 버튼은 글자 하나씩 표시합니다. 문제 목록은 선택 여부와 관계없이 테두리가 있으며 현재 문제는 초록색으로 강조합니다. 작성 중 내용은 브라우저에도 자동 보관합니다. JSON 저장·가져오기, 예시 불러오기, 여러 문제 붙여넣기 메뉴는 사용하지 않습니다.

저장하면 `AB7K2M` 같은 영문·숫자 6자리 **불러오기 코드**를 발급합니다. I/O/0/1처럼 헷갈리는 문자는 사용하지 않습니다. 저장 완료 안내와 내 퀴즈 목록에서 코드를 보고 복사할 수 있습니다. **퀴즈 불러오기 → 코드로 불러오기**에 입력하면 다른 브라우저·기기·포트에서도 같은 서버에 저장된 제목·목표 인원·문제·정답을 불러옵니다. 소문자도 허용합니다. 같은 제목 덮어쓰기는 기존 코드를 유지하고 다른 제목 저장은 새 코드를 발급합니다. 기존 저장본에도 코드만 추가하며 내용·ID·소유권·저장 시각을 유지합니다.

코드를 아는 사람은 문제와 정답을 읽을 수 있습니다. 다른 사람의 코드를 불러오면 편집용 사본이며 저장 시 본인 보관함에 새 ID·코드로 저장합니다. 원본 수정·삭제 권한은 원래 브라우저의 소유 키로 확인합니다. 원본 삭제 시 그 코드는 무효가 되며 이미 별도로 저장한 사본은 유지합니다. 삭제한 코드를 새 퀴즈에 재사용하지 않습니다. 코드 입력은 IP당 분당 30회로 제한합니다.

로그인 없이 같은 브라우저에 보관한 비밀 키로 내 보관함을 구분합니다. 비밀 키 원문은 서버 파일에 저장하지 않습니다. 다른 브라우저나 포트에서는 보관함 전체가 자동 연결되지는 않지만 퀴즈별 코드로 불러올 수 있습니다. 동일한 `data/quizzes.json`을 쓰는 여러 서버는 파일 잠금과 읽기 전 최신 저장본 확인으로 코드와 저장 내용을 공유합니다. 별개 서버·별개 저장 파일로 코드가 자동 복제되지는 않습니다.

**방 만들기**는 현재 작성 중인 내용으로 바로 방을 엽니다. 저장창을 표시하거나 보관함을 자동으로 수정하지 않습니다. 보관하려면 **퀴즈 저장**을 따로 누릅니다. 게임 방은 별도 메모리 상태이며 참가자가 있을 때만 유지합니다. 방장이 나가면 남은 사람 중 입장 순서가 가장 빠른 사람이 방장을 맡습니다. 원래 만든 사람이 재입장해도 현재 방장을 빼앗지 않습니다. 유령과 관전자도 승계 대상이며 저장한 퀴즈의 소유권은 넘어가지 않습니다.

마지막 사람이 나가거나 연결이 끊기면 방과 타이머를 정리하고 공개 목록에서 제거합니다. 저장한 퀴즈는 유지됩니다. 현재 재접속 유예는 없으며 서버 재시작 후에도 진행 중이던 게임 방은 복원하지 않습니다. 퀴즈를 불러와 새 방을 열면 새 방 ID로 시작합니다. 봇 기능과 삭제한 방 복원 기능은 없습니다.

기존 `data/rooms.json`의 문제는 새 보관함으로 이전합니다. 삭제했던 방의 정의도 보존하며, 원래 방 관리 키를 가지고 있는 브라우저에서만 내 퀴즈로 연결할 수 있습니다. 이전 파일은 원본 그대로 남깁니다. 서버 퀴즈 파일은 원자적으로 교체하고 직전 저장본을 `.bak`로 보관합니다.

## 게임 조작과 판정

- OX: 무대 터치·방향키·WASD, 세로 화면 왼쪽 아래의 반투명 조이스틱으로 이동합니다. PC·모바일 모두 O/X를 좌우로 배치합니다. 화면 회전 시 답과 이동 위치를 유지합니다.
- 객관식: 보기 버튼 또는 2×2 구역 이동을 선택합니다. 버튼 선택은 이동 좌표와 독립적입니다.
- 소수결: O/X 대신 왼쪽·오른쪽 구역을 선택합니다. 제한시간이 끝날 때 해당 라운드 참가자 수가 적은 쪽이 통과하고, 동수는 서버 난수로 승리 구역을 한 번 결정합니다. 부활전은 참가한 유령만 집계하고 승리 구역의 유령만 부활합니다. 관전자·중도 입장자는 집계하지 않으며 퇴장자는 제외합니다. 빈 구역도 0명으로 계산하고, 일반 라운드에서 전원 탈락하면 기존 직전 생존자 기준 종료·추첨 규칙을 적용합니다. 고정 정답을 작성하지 않으며 저장·코드 불러오기와 라운드 안내 문구 편집을 지원합니다. 화면에 현재 좌우 인원을 표시하고 판정 후 집계와 무작위 결과는 인원 변동에도 유지합니다.
- 주관식: 비공개 답을 입력하고 제출합니다. 마감 전 수정·재제출할 수 있으며 마지막 제출값을 판정합니다. 여러 정답은 `서울, 서울특별시`처럼 쉼표로 구분합니다. 같은 문제에서 다른 사람의 입장·퇴장·연결 종료·방장 변경은 입력창을 숨기거나 답안·커서·포커스를 초기화하지 않습니다. 새 문제 또는 새 게임에서만 답안을 비웁니다. 객관식 선택과 제출한 답안 안내도 입장·퇴장 때 유지합니다. 채팅창은 같은 문제의 인원 변경과 정답 공개→쉬는 시간 전환에는 유지하고, 다음 문제 시작 때 닫습니다.
- 탈락하면 기존 연보라색 유령 그래픽으로 전환하고 하단 관전 구역(x ±7.5, z 8.6~9.8)에서만 이동합니다. 부활하면 선택했던 아바타로 돌아옵니다. 부활전에는 유령이 참가하고 기존 생존자는 관전합니다.
- 문제 결과 생존자가 당첨 목표 **이하**이면 남은 생존자 전원 당첨 후 종료합니다. 최종 라운드 후 목표를 초과하면 생존자 중 목표 인원만 추첨합니다.
- 일반 문제에서 전원 오답이면 직전 생존자 기준으로 즉시 종료하며, 목표보다 많으면 목표 인원만 추첨하고 목표 이하면 전원 당첨됩니다. 이후 예약 문제·부활전은 진행하지 않습니다. 방장은 다른 참가자와 같은 판정과 추첨을 적용합니다.

세로 화면 왼쪽 아래(가로 32px·아래 42px 여백, 안전 영역 추가)에는 반투명 조이스틱이 겹쳐 표시됩니다. 객관식 이동형의 긴 보기는 세로 화면에서 한 열로 줄바꿈·스크롤하며 조이스틱과 겹치지 않습니다. 드래그 강도에 따라 속도를 조절하며 손을 떼거나 입력창·화면 전환·포인터 취소가 발생하면 즉시 멈춥니다. 가로 화면이나 이동할 수 없는 단계에서는 숨깁니다. 무대 앞벽은 흰색으로 채워 아래 유령 관전석과 단차를 구분합니다. 하단 조작 버튼 뒤까지 무대가 이어집니다. 게임 카메라는 유령 관전석 쪽에서 무대를 낮게 바라보는 2.5D 원근 시점입니다. 바닥 기준 24도로 무대 앞벽과 높이 차이를 보여주며 좌우 회전 없이 무대 가로선은 수평으로 유지합니다. PC와 모바일은 같은 고정 가로형 맵(가로 배율 1.4, 깊이 배율 1.3)을 사용합니다. PC·가로 화면에서는 전체 맵을, 세로 화면에서는 주변 일부를 보여주고 내 캐릭터를 따라 카메라 위치만 좌우로 부드럽게 이동합니다. 중앙 여유 구간과 양 끝 이동 제한을 두며 카메라 각도·확대율은 이동 중 고정합니다. 유령도 같은 방식으로 추적하고 화면 회전은 답과 좌표를 바꾸지 않습니다. 문제 길이는 상단 공간과 카메라 구도에만 반영하며 맵 자체를 늘리지 않습니다. 주관식 답안창·객관식 보기·채팅창 모두 맵 위에 겹쳐 표시하고 캔버스 영역이나 카메라를 줄이지 않습니다. 채팅·주관식 입력 중에는 키보드 높이가 변해도 구도를 고정합니다. 일반 채팅을 닫거나 게임 단계가 바뀌면 정상 화면 배치로 돌아갑니다. 유령의 서버 이동 범위는 유지하며 화면상의 관전석은 무대 앞벽 바깥으로 배치합니다. 시작과 일반 라운드 전환에서 위치를 유지하고 역할이 바뀌면 이전 위치를 기억합니다. 머리 위 닉네임·상태·채팅은 투영된 머리 위치를 기준으로 각각 5px·3px·5px 간격으로 쌓아 거리가 멀거나 가까워져도 뜨지 않도록 합니다. 닉네임과 채팅은 별도로 표시하며 채팅은 최대 40자, PC 16px, 모바일 11px의 진한 글자로 자동 줄바꿈합니다. 생존·유령·목표는 ROUND와 타이머 사이에 작게 표시합니다. 사회자는 맵 안 중앙 단상에 서고 머리에 연결된 말풍선으로 안내합니다. 문제 아래 버튼은 26px 높이이며 ‘나 찾기’와 ‘게임 규칙’을 붙여 배치합니다.

문제는 최대 100자, 주관식 정답은 쉼표로 나눈 각 정답당 최대 30자, 객관식 보기도 각각 최대 30자입니다. 글자 수는 유니코드 코드 포인트 기준이며 주관식 복수 정답 전체는 1,000자까지 보관합니다. 입력·서버 저장·방 생성·답안 제출에서 검사합니다. 기존 긴 저장본을 자동으로 자르지 않으며 새 제한에 맞춰 수정한 뒤 저장할 수 있습니다. 긴 본문·보기는 줄바꿈하고 작은 화면에서 필요한 부분만 스크롤하며 타이머를 유지합니다. 사회자는 맵 안 단상에 표시하며 말풍선 꼬리는 머리를 향합니다. 모바일 카메라 이동으로 사회자가 화면 밖에 나가면 말풍선도 숨깁니다. 종료 결과창은 게임당 한 번만 자동으로 열립니다. **화면 닫기(결과보기)**는 결과를 보관한 채 창만 닫고 **결과 보기**로 다시 열 수 있습니다. 방장의 **재시작하기(결과 초기화)**는 당첨 결과와 탈락 상태를 지우고 전원이 다음 게임을 준비하는 대기 상태로 돌아갑니다.

## 검증

```powershell
npm test
```

71개 자동 테스트에서 퀴즈 보관·소유권·기존 데이터 이전·미완성 저장·저장 실패 롤백·빈 방 제거와 OX/주관식/객관식 판정, 목표 이하 조기 종료, 유령·부활, 결과창 중복 방지, 추첨을 확인합니다. 방장 오답/참가자 정답의 단독 당첨과 3인 추첨의 모든 순열에서 방장 우대가 없는지도 검증합니다.

별도 브라우저에서 서버 저장→불러오기→덮어쓰기→서버 재시작, 다른 사용자 보관함 분리, 실제 2인 게임의 일반 참가자 당첨, 방장 승계와 재입장, 마지막 퇴장 후 방 제거를 확인했습니다. 편집기는 320×568, 390×844, 1280×800에서, 사회자는 PC 1280×720부터 1920×1080 및 모바일 세로·가로에서 확인했습니다. 실제 100명 접속 성능과 OS 가상 키보드는 별도 기기 검증 대상입니다.

테스트는 `OX_DISABLE_PERSISTENCE=1`로 파일 저장을 끌 수 있습니다. `OX_QUIZ_FILE`로 보관함 경로를 지정하거나, `OX_DATA_FILE`을 지정하면 기존 방 이전 파일과 그 옆의 `.quizzes.json` 파일을 테스트에 사용할 수 있습니다.




처음 접속한 브라우저에는 `리마인000`~`리마인999` 형식의 랜덤 닉네임을 생성합니다. 직접 변경한 닉네임과 생성한 닉네임은 이 브라우저의 `ox-nickname-v1`에 보관합니다. 기존 로컬 초안의 닉네임은 유지하지만 공용 복구용 초안의 닉네임은 가져오지 않습니다. 닉네임을 비운 채 방 생성·입장하면 같은 형식으로 자동 생성합니다.

## 멤버 아바타

로비의 닉네임 아래 **아바타 선택**에서 기본·원이·리브·미나미·메이·제나를 선택합니다. 참고 이미지와 실제 게임에 사용하는 3D 전신 미리보기를 함께 표시합니다. 선택은 이 브라우저의 `ox-avatar-v1`에 보관하며 방 만들기와 입장 시 서버에 전송합니다. 같은 멤버의 3D 외형은 본인과 다른 참가자 화면에 동일하게 표시됩니다. 유령과 부활·새 게임 전환에서도 선택을 유지합니다. 현재 입장한 뒤의 변경은 지원하지 않으며 로비에서 다음 입장용 아바타를 고릅니다.

사용자가 제공한 `radiant-noether/Images/*_focus.png`, `*_break.png`를 원본 그대로 `client/assets/avatars/`에 보관했습니다. 그림을 그대로 3D로 복원한 모델이 아니라, 헤어·머리색·의상·장신구를 참고해 게임의 둥근 3D 스타일로 만든 캐릭터입니다. 선택창 이미지는 focus 그림이며 NPC 사회자는 기존 모습을 유지합니다. 미리보기는 하나의 WebGL 캔버스를 공유하고 선택창을 닫으면 렌더링을 멈춥니다.

6인 실제 접속에서 방 생성·입장·로컬/다른 참가자 외형 일치, 선택 후 새로고침, 320×568·390×844·844×390·1280×800의 선택창 넘침을 확인했습니다. 알 수 없는 아바타 ID는 서버에서 기본으로 처리합니다.

첨부된 `232D454057C1329C27`에서 `CM3D2_PRESET` 헤더와 138×200 PNG 미리보기를 확인했습니다. 모델 메시가 아닌 외형 설정 및 외부 부품 참조이므로 파일 자체를 게임에 불러오지는 않습니다. 미리보기의 애니 스타일을 참고해 멤버 모델에 큰 눈·속눈썹·가늘어진 몸통·가닥 형태 앞머리·툰 음영을 적용했습니다. 원본 프리셋과 참고 이미지는 수정하지 않았습니다.

소수결 추가 검증: 자동 테스트 80개를 통과했습니다. 격리된 실제 브라우저에서 320×568·390×844·844×390·1280×800의 30자 한글·영문·이모지·띄어쓰기 보기 네 개를 끝까지 읽고 각 구역으로 이동했으며, 소수결 작성·저장·불러오기·일반 판정·유령 부활전·동수 무작위 판정·판정 후 중도 입장을 확인했습니다.
